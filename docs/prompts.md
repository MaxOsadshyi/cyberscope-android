# Prompts: запити до coding agent

Агент: GitHub Copilot (режим Agent) у VS Code. Задача: «пояснення прогнозу» (розбивка розрахунку).
Типи запитів відповідають методичці: Аналіз, План, Реалізація, Debugging, Тестування, Підсумок.

## 8. Debugging: помилка округлення

**Тип:** Debugging

**Запит:**

```
У застосунку для FaZe Clan показується «Win rate: 57%», хоча backend повертає team_b_win_rate = 0.58, а внесок 0.348 правильний. Знайди першопричину в MainActivity.kt і запропонуй мінімальне виправлення. Також скажи, чи так само постраждають рядки з відсотками прогнозу. Змінюй тільки MainActivity.kt, нових залежностей не додавай, формат відповіді backend не чіпай. Commit і push не роби.
```

**Як знайдено помилку:** не тестами, а під час звірки скріншота застосунку з відповіддю backend. На екрані FaZe Clan мав 57%, у відповіді було 0.58.

**Першопричина:** `(0.58 * 100).toInt()`. У числах з плаваючою комою `0.58 * 100` дорівнює `57.99999999999999`, а `toInt()` відкидає дробову частину. Для всіх шести команд помилка лише в FaZe Clan; відсотки прогнозу (0.53 та 0.47) для поточних даних не страждали, небезпечні значення 0.57 і 0.58.

**Виправлення (`346c2ab`):** `toInt()` замінено на `roundToInt()` (імпорт `kotlin.math.roundToInt`) у чотирьох місцях: два win rate і два відсотки прогнозу (останні превентивно). Інші файли й залежності не змінювались.

**Що перевірено:** `git show 346c2ab` (змінено лише `MainActivity.kt`), перезапуск застосунку: FaZe Clan показує 58%, прогноз лишився 53% / 47%.
