# Тестування

## Поточний стан

Власних автоматичних тестів у репозиторії **поки немає**. У `mobile/app/src/test` і `mobile/app/src/androidTest` лежать лише шаблонні Example-тести, створені Android Studio, вони нічого не перевіряють у застосунку.

## Запуск системи для перевірки

```
# 1. backend
cd backend
venv\Scripts\activate
uvicorn main:app --reload

# 2. емулятор запущено, тунель до backend (повторювати після перезапуску емулятора)
adb reverse tcp:8000 tcp:8000

# 3. Android Studio: Run
```

Якщо `adb` не знайдено в PowerShell:
`& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8000 tcp:8000`

## Ручні сценарії

| Сценарій | Кроки | Очікуваний результат |
|---|---|---|
| Коректні дані | Обрати Natus Vincere і FaZe Clan, натиснути «Прогнозувати» | 53% / 47% і текст пояснення |
| Не обрано команди | Натиснути кнопку без вибору | «Помилка: Оберіть обидві команди» |
| Однакові команди | Обрати одну команду в обох списках | «Помилка: Оберіть дві різні команди» (400 від backend) |
| Невідома команда | У Swagger відправити `"team_a_name": "Navi"` | 404, `"Команду 'Navi' не знайдено"` |
| Порожнє поле | У Swagger відправити `"team_a_name": ""` | 422 |
| Backend недоступний | Зупинити `uvicorn`, натиснути кнопку | Індикатор зникає, показується помилка з'єднання |
| Повторний запит | Після помилки запустити backend, змінити вибір, натиснути кнопку | Новий результат без перезапуску застосунку |
| Здоров'я сервісу | Відкрити `/health` | `{"status": "ok"}` |

## Перевірка API без застосунку

Swagger UI: `http://127.0.0.1:8000/docs`. Приклад із PowerShell:

```
curl.exe -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" -d "{\"team_a_name\": \"Vitality\", \"team_b_name\": \"MOUZ\"}"
```

## Регресійна перевірка сценарію ЛР2

Після будь-яких змін перевірити: застосунок запускається; список з 6 команд завантажується; прогноз для двох різних команд показує відсотки; помилки відображаються; сума ймовірностей у JSON дорівнює 1.

## Заплановані автотести (ЛР3)

Інструмент: `pytest` з `TestClient` від FastAPI (потребує бібліотеки `httpx`). Це нові залежності, їх обґрунтування записується в `decisions.md`.

```
cd backend
pip install pytest httpx
pytest
```

Що покрити:

- `/health` повертає 200 і `{"status": "ok"}`;
- `/teams` повертає 6 команд;
- `/predict` для двох різних команд: код 200, сума ймовірностей дорівнює 1, відсотки збігаються з розрахунком за формулою;
- `/predict` з однаковими командами: 400; з невідомою командою: 404; з порожнім полем: 422;
- нові поля розбивки розрахунку (після реалізації функції).

Для mobile власних автотестів немає (є лише шаблонні), натомість ручні сценарії з таблиці вище.
