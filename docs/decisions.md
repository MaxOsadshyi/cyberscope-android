# Технічні рішення

Формат: рішення, причина, наслідки. Нові рішення додаються вгору списку.

## D-9. Тести backend через pytest і httpx (ЛР3, заплановано)

- **Рішення:** додати `pytest` і `httpx` для автотестів `/predict`, `/teams`, `/health`.
- **Причина:** методичка вимагає тестів для нової поведінки, а в проєкті їх немає. `httpx` потрібен для `TestClient` у FastAPI.
- **Наслідки:** нові dev-залежності. Додаються в `requirements.txt` або окремий `requirements-dev.txt`.

## D-8. Один репозиторій із папками `mobile/` і `backend/`

- **Причина:** методичка вимагає одного Git-репозиторію з обома частинами; той самий репозиторій використовується для ЛР1, ЛР2 і ЛР3.
- **Наслідки:** стани лабораторних позначаються тегами `lab1`, `lab2`.

## D-7. Відкритий CORS (`allow_origins=["*"]`)

- **Причина:** спрощує розробку. Мобільний застосунок не є браузером, тож для нього CORS не потрібен, це запас на майбутній веб-клієнт.
- **Наслідки:** для продакшену потрібен обмежений список джерел.

## D-6. HTTP замість HTTPS (`usesCleartextTraffic="true"`)

- **Причина:** локальний backend працює без TLS, а Android блокує HTTP за замовчуванням.
- **Наслідки:** допустимо лише для розробки.

## D-5. Доступ емулятора до backend через `adb reverse`

- **Рішення:** `adb reverse tcp:8000 tcp:8000` і адреса `http://127.0.0.1:8000`.
- **Причина:** стандартна адреса `10.0.2.2` давала timeout (`failed to connect ... after 5000ms`) на використаному образі емулятора.
- **Наслідки:** команду треба повторювати після перезапуску емулятора.

## D-4. `HttpURLConnection` і `org.json` замість Retrofit/Ktor

- **Початковий план:** Ktor Client.
- **Рішення:** вбудований `HttpURLConnection` у `Dispatchers.IO`.
- **Причина:** не потребує нових залежностей і змін у `libs.versions.toml`, менше ризик зламати Gradle-збірку.
- **Наслідки:** JSON розбирається вручну, нове поле додається в кількох місцях.

## D-3. Вагова формула замість ML-моделі

- **Рішення:** `score = win_rate·0.6 + rating·0.4`, ймовірність як частка від суми балів.
- **Причина:** методичка допускає базовий алгоритм і не вимагає навчання моделі. Обсяг доступних даних замалий для навчання.
- **Наслідки:** прогноз демонстраційний (див. `ai-component.md`). Формулу можна замінити, зберігши формат відповіді.

## D-2. Hardcoded `TEAMS_DB`

- **Причина:** MVP має показати повний потік mobile → backend → результат, а не інтеграцію з зовнішніми джерелами.
- **Наслідки:** дані демонстраційні. Список команд клієнт бере через `GET /teams`, тому назви завжди збігаються з довідником.

## D-1. Python, FastAPI, Pydantic для backend

- **Причина:** рекомендований методичкою стек. Pydantic дає валідацію, FastAPI дає автоматичний Swagger UI.
- **Наслідки:** запуск через Uvicorn, залежності в `backend/requirements.txt` (`fastapi`, `uvicorn`, `pydantic`).
