# Правила роботи coding agent з репозиторієм CyberScope

Ці правила діють для кожної задачі. Якщо задача суперечить правилу, спочатку запитай автора.

## Перед змінами

1. Прочитай `docs/` (насамперед `architecture.md`, `api-contract.md`, `known-limitations.md`) і перевір структуру репозиторію.
2. Поясни поточну реалізацію своїми словами.
3. Запропонуй план з критеріями готовності та перерахуй файли, які змінюватимуться.
4. Не починай реалізацію, доки автор не підтвердив план.

## Під час змін

- Роби один завершений крок за раз, без непов'язаного рефакторингу.
- Не переписуй весь проєкт заради локальної задачі.
- Не змінюй API-контракт (`/predict`, `/teams`, `/health`) без пояснення та оновлення `docs/api-contract.md`.
- Поля в Pydantic-моделях (`backend/main.py`) і Kotlin-класах (`mobile/.../ApiModels.kt`) мають збігатися за назвами. Змінюючи одне, змінюй і друге.
- Не додавай залежності без обґрунтування в `docs/decisions.md`.
- Не зберігай секрети (API keys, токени, паролі) у коді, prompts або Git. Використовуй синтетичні дані.
- Не чіпай файли поза задачею: `local.properties`, `venv/`, `build/`, `.gradle/`.

## Після змін

- Додай або онови тести для нової поведінки (див. `docs/testing.md`).
- Переконайся, що сценарій ЛР2 не зламано: вибір двох команд → прогноз у відсотках.
- Онови документацію, якщо змінилась поведінка, API чи структура.
- Підсумуй: що змінено, які команди перевірки виконано, які є ризики.

## Корисні команди

```
# backend
cd backend
venv\Scripts\activate
uvicorn main:app --reload

# mobile (емулятор бачить backend через тунель)
adb reverse tcp:8000 tcp:8000
```
