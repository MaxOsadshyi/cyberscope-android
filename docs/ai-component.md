# Інтелектуальний компонент

## Що це

Це **не навчена ML-модель**, а детермінована евристика: вагова формула в функції `predict()` у `backend/main.py`. Методичка ЛР2 допускає «базовий алгоритм». Результат завжди однаковий для однакових вхідних даних, нічого не навчається.

## Призначення

Перетворити статистику двох команд на ймовірність перемоги кожної з них і короткий текст пояснення.

## Вхідні дані

Назви двох команд. Статистику backend бере зі словника `TEAMS_DB`:

| Команда | win_rate | rating |
|---|---|---|
| Natus Vincere | 0.65 | 1.15 |
| FaZe Clan | 0.58 | 1.05 |
| Vitality | 0.70 | 1.20 |
| G2 Esports | 0.60 | 1.08 |
| MOUZ | 0.55 | 1.02 |
| Spirit | 0.62 | 1.10 |

Це приблизні демонстраційні значення, а не реальна статистика.

## Алгоритм

```
score = win_rate * 0.6 + rating * 0.4
P(A)  = score_A / (score_A + score_B)
P(B)  = 1 - P(A)
```

Обидві ймовірності округлюються до двох знаків (`round(..., 2)`). Ваги 0.6 і 0.4 вибрані вручну, а не підібрані на даних.

Пояснення формується з імені команди з більшою ймовірністю: `"<команда> має вищий win rate та рейтинг за останні матчі"`.

## Приклад розрахунку

Natus Vincere проти FaZe Clan:

- score NAVI = 0.65·0.6 + 1.15·0.4 = 0.390 + 0.460 = 0.850
- score FaZe = 0.58·0.6 + 1.05·0.4 = 0.348 + 0.420 = 0.768
- P(NAVI) = 0.850 / 1.618 ≈ 0.525 → 0.53; P(FaZe) = 0.47

## Формат виходу

`team_a_win_probability`, `team_b_win_probability` (float, сума 1) та `explanation` (string). Деталі в `api-contract.md`.

## Обмеження

- Прогнози завжди близькі до 50%: діапазон `win_rate` (0.55–0.70) і `rating` (1.02–1.20) вузький. Навіть найсильніша команда проти найслабшої дає приблизно 55/45.
- Формула не враховує карту, форму гравців, історію особистих зустрічей, турнірний контекст.
- Ваги не перевірялись на реальних результатах матчів, точність прогнозу не оцінювалась.
- Текст пояснення фіксований і не відображає складових розрахунку. Він правдивий лише доки в `TEAMS_DB` команда з більшим `win_rate` має і більший `rating` (для поточних 6 команд це так).
- При рівних округлених ймовірностях `leader` вибирається як команда B без підстав.

## Fallback і помилки

- Зовнішніх сервісів немає, тож відмови AI-провайдера бути не може.
- Невідома команда або однакові команди дають контрольовану помилку (404 / 400), а не прогноз.
- Якщо формулу колись замінять на модель або зовнішній API, її збій має повертати контрольовану відповідь, а запасним варіантом може слугувати поточна формула.
