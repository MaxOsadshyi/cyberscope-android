# Відомі обмеження та ризики

## Дані та AI

| Обмеження | Деталі |
|---|---|
| Дані команд у коді | `TEAMS_DB` містить 6 команд з демонстраційною статистикою. Реальних джерел (HLTV, Liquipedia) немає |
| Прогноз це формула, а не модель | Ваги 0.6 / 0.4 вибрані вручну, точність не перевірялась |
| Прогнози близькі до 50% | Через вузький діапазон вхідних показників (див. `ai-component.md`) |
| Фіксований текст пояснення | Не показує складових розрахунку. Зараз правдивий лише тому, що в `TEAMS_DB` команда з більшим `win_rate` має і більший `rating`. Зміна даних може зробити його хибним |
| Рівні ймовірності | При однакових округлених значеннях `leader` стає командою B без підстав |

## Backend

| Обмеження | Деталі |
|---|---|
| Немає автотестів | Перевірка лише вручну (Swagger, застосунок) |
| Конфігурація не винесена в environment variables | Ваги формули, дані, налаштування прописані в коді |
| `allow_origins=["*"]` | Відкритий CORS, прийнятно лише для розробки |
| Немає логування й обмеження частоти запитів | Для MVP не потрібно, для продакшену потрібно |
| Один файл `main.py` | Моделі, дані, маршрути й логіка змішані |

## Mobile

| Обмеження | Деталі |
|---|---|
| Список команд завантажується один раз | `LaunchedEffect(Unit)` викликає `getTeams()` при відкритті екрана. Якщо backend був недоступний, команди з'являться лише після перезапуску застосунку |
| Помилка 422 показується технічно | `detail` у Pydantic це масив, клієнт читає його як рядок. У нормальному сценарії не виникає, бо команди обираються зі списку |
| Однакові команди перевіряє лише backend | Застосунок перевіряє лише, що обрано обидві |
| `usesCleartextTraffic="true"` | Дозволений незашифрований HTTP, потрібен лише через локальний backend |
| Адреса backend у коді | `BASE_URL` константа в `ApiClient.kt` |
| Ручний розбір JSON | Нове поле відповіді треба додати і в `ApiModels.kt`, і в `ApiClient.kt` |
| Назви за замовчуванням | Пакет `com.example.helloworld`, тема `HelloWorldTheme` |

## Середовище розробки

| Обмеження | Деталі |
|---|---|
| Тунель `adb reverse` скидається при перезапуску емулятора | Команду треба повторювати. Без неї застосунок показує «Failed to connect to /127.0.0.1:8000» |
| `10.0.2.2` на використаному емуляторі давала timeout | Образ Android API 37.2 (preview). Тому використано `adb reverse` |
| Git-репозиторій не повинен лежати в OneDrive | Синхронізація може пошкодити `.git` |

## Ризики при змінах

- Розбіжність назв полів між Pydantic-моделями і Kotlin-класами призводить до помилки розбору JSON.
- Зміна `PredictResponse` ламає старий клієнт, якщо поле прибрати. Нові поля безпечні, якщо старі залишаються.
- Додавання бібліотек у Gradle може зламати збірку, тому застосунок навмисно не використовує Retrofit/Ktor.
