# Огляд проєкту

## Проблема

Фанати CS2 збирають інформацію з розрізнених джерел (HLTV, соцмережі). Такі сервіси показують сирі дані, але не інтерпретують їх: користувач сам вирішує, яка команда сильніша.

## Користувач

Глядач або фанат кіберспорту (CS2), якому цікаво швидко порівняти дві команди перед матчем.

## Ідея продукту

Мобільний застосунок **CyberScope** з розкладом турнірів, профілями команд і гравців та прогнозом результату матчу. Повна концепція описана в Лабораторній роботі 1.

## Основний сценарій MVP (ЛР2)

1. Користувач відкриває застосунок. Він завантажує список команд з backend.
2. Обирає Команду A і Команду B.
3. Натискає «Прогнозувати».
4. Backend перевіряє команди та рахує ймовірність перемоги за формулою.
5. Застосунок показує відсотки обох команд і коротке пояснення.

## Межі MVP

Реалізовано:

- вибір двох команд зі списку (6 команд CS2);
- прогноз у відсотках з текстовим поясненням;
- стани інтерфейсу: початковий, завантаження, успіх, помилка;
- обробка помилок (однакові команди, невідома команда, недоступний backend).

Не реалізовано (поза межами MVP):

- розклад турнірів, список матчів, профілі гравців, історія зустрічей, пошук і фільтри;
- реальні джерела даних (HLTV, Liquipedia): дані команд зберігаються в коді;
- навчена ML-модель: прогноз рахує проста вагова формула;
- база даних, авторизація, push-сповіщення.

## Технології

| Частина | Стек |
|---|---|
| Mobile | Kotlin, Jetpack Compose, `HttpURLConnection`, `org.json` |
| Backend | Python 3.12, FastAPI, Uvicorn, Pydantic |
| Зв'язок | HTTP + JSON, для емулятора `adb reverse tcp:8000 tcp:8000` |

## Структура репозиторію

- `mobile/`: проєкт Android Studio
- `backend/`: FastAPI-сервіс
- `docs/`: Knowledge Base
